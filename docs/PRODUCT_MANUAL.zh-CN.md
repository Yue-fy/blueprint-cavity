## 1. 产品愿景、用户与边界

Blueprint 与 Cavity 共同提出一个具体问题：当模型从图纸或科研结果中给出一个数字时，怎样让人检查“这个数是怎么来的、依据是什么、哪里可能错”？建筑量算是第一种实现。模型得到一张图纸和一份工作要求，可以读取 PDF、观察图像、计算几何，最终提交数量、单位、置信度、证据框和假设。独立 verifier 按公开规则返回奖励。用户也能在相同图纸上操作并检查相同评分器。

产品把任务、输入、答案格式、评分、回放和来源组织为可检查的工作流程。一个漂亮的结果数字如果缺少运行标识、对应图纸或有效答案，不会被补成“成功”。一个模型数量正确但框选范围不足，也可能得到低于 1 的奖励。界面让这些差异可见，便于观察策略和错误。

Blueprint 与 Cavity 是产品首页上并列的两条案例路线，用户可直接选择任何一条。Blueprint 用建筑量算检验图纸理解、工具动作与奖励；Cavity 让人探索 hBN 纳米腔的预计算模式、测量窗口与本地 AI 回复检查。同等入口说明两者都值得被发现，不表示它们拥有同一种实验：建筑有真实历史 Harbor benchmark，Cavity 当前是科学交互展示与本地 checker，没有新增在线科学 agent 或 hBN Harbor 奖励矩阵。

Boundary lab 另有独立重写的数学 toy、证明、系数检查与 16 条 Harbor 记录，其中 8 条是学习模型尝试。它不能替 Cavity 的预计算场建立实验验证；Cavity 五个面板也不是五道新增 Harbor 题。三种证据均保留自己的参数、来源与结论边界。

主要适用人群包括：评估模型工具使用能力的研究者、希望理解量算过程的工程师和估算人员、查看任务与奖励契约的竞赛评审、检查数学与数值一致性的科研人员，以及维护演示和复现材料的开发者。建筑专家可评价题目范围与计量约定，机器学习人员可分析工具轨迹与校准，科研人员可检验推导与观测量是否匹配，各自不必把其他层的结论当作已被自动证明。

使用范围也很明确。36 道建筑题目是可验证环境示例，不能代替正式工程预算或专业复核；三张源图不足以证明新建筑泛化。toy 的证明只适用于定义、参数域与指定指数；它不验证原始研究项目。hBN 展示不建立场收敛、探测量等价或论文复现成功。项目完成的是环境、基线运行、可检查的产品与展示素材，没有更新模型权重，也没有后训练增益结果。

## 3. 36 道建筑任务的构成

任务集合由 12 个场景乘以三种输入条件组成。`vector` 是矢量 PDF，适合同时检索文字和读取图形对象；`clean` 是完整页面的清晰 PNG；`scan` 是人为生成的合成退化 PNG。三种条件保留同一图纸范围和物理尺度，以便比较输入条件影响。图纸不是 36 栋独立建筑，场景之间也不是完全独立样本。

| 家族 | 场景数 | 矢量 PDF | 清晰 PNG | 合成扫描 PNG | 合计 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 房间面积 | 2 | 2 | 2 | 2 | 6 |
| 踢脚线与周长 | 3 | 3 | 3 | 3 | 9 |
| 门窗套数 | 2 | 2 | 2 | 2 | 6 |
| 楼板面积 | 2 | 2 | 2 | 2 | 6 |
| 管线与设备 | 3 | 3 | 3 | 3 | 9 |
| 总计 | 12 | 12 | 12 | 12 | 36 |

下面列出场景的真实范围。任务 ID 后加 `-vector`、`-clean` 或 `-scan` 即为具体任务，例如 `bp-10-vector`。

| 场景 | 工作要求 | 操作时特别注意 |
| --- | --- | --- |
| bp-01 | 健身房地面面积 | 找到正确房间，按题目范围恢复尺度与内边界 |
| bp-02 | 洗衣房面积 | 属于留出场景，不能据此声称是新建筑 |
| bp-03 | 多功能厅踢脚线 | 周长扣门洞，内部折叠隔断按约定排除 |
| bp-04 | 洗衣房踢脚线 | 保留专家与可辩护替代测量的差异 |
| bp-05 | 厨房踢脚线 | 房间不是可随意简化的矩形，传菜口下方保留墙体的约定影响结果 |
| bp-06 | 教室翼西立面窗数 | 按立面方向与范围计数，属于留出场景 |
| bp-07 | 入口门厅滑动门套数 | 套数与门扇数不同，双门按一套处理 |
| bp-08 | 左侧 300 mm D16 六板矩形区域面积 | 题目明确排除凸出的楼梯区域 |
| bp-09 | 150 mm、D13 @ 300 楼板毛平面面积 | 沟槽扣除前的毛面积；标高不是面积，是三条件共同的判断陷阱 |
| bp-10 | 带流量控制器的非冲击止回阀数量 | 按 CV 标签与设备语义识别，不能误计 FSCV |
| bp-11 | FP 燃油泵数量 | 看管线图设备标签，属于留出场景 |
| bp-12 | 吸入总管尺寸 | 这是直径/尺寸问题，虽在管线家族也不应默认回答数量 |

三个 `bp-09` 变体是同一场景的三个陷阱题，不是三种互不相关的陷阱。留出集共有 9 题，全部来自 `bp-02`、`bp-06`、`bp-11`，每个场景的三种输入条件保持在一起。其余 27 题为训练场景。所有场景整理时都被检查过，且留出集和训练集共享三张源图，因此“holdout”只表示预留场景划分，不表示盲测。

三张图纸分别是英国教育部特殊学校平面、USACE 楼板与基础标准图、USACE 管线标准图。清晰栅格最长边为 4096 像素。合成扫描依次加入模糊、对比度变化、确定性噪声与 JPEG 压缩，再保存为 PNG；没有裁剪、倾斜、旋转或后续尺寸变化。这一设计让坐标与尺度可比较，但没有涵盖真实扫描中的折痕、镜头畸变、缺页等情况。

gold 的来源必须与证据框来源分开理解。某些数量与方法来自获授权的专家参考；某些开发参考由 agent 测量；新增框由整理 agent 标注。洗衣房踢脚线保留 9.96 m 与 10.08 m 两种接受值，体现约定与测量分歧。专家指出的错误矩形厨房面积、存在 ±3 不确定性的全图门数等没有被纳入当前场景。

### 4.2 Cavity 入门页：从物理问题到可操作检查

#cavity 页标题为 `Light, confined. Claims, examined.`，先解释hBN中红外光耦合晶格振动，以及模式是特征场型、共振是响应较强的频率。它帮助访客知道该看什么，再进入真实模块。此页本身是静态入门，没有模拟参数滑杆、评分器或模型调用；操作链接进入 /hbn/ 后才使用既有场图、窗口与 checker。

| 入门操作 | 跳转 | 访客要检查的内容 |
| --- | --- | --- |
| Open Cavity Lab / Explore Cavity Lab | /hbn/ | 完整五模块研究页 |
| Rotate the cavity and change frequency / Explore the fields | /hbn/#tab=1 | 旋转示意场、切保存频率，随后查看方腔与mode map |
| Try the window experiment | /hbn/#tab=4 | 固定同一谱，改变分析窗口，看基线、线宽与Q如何变化 |
| Try the AI reply checker / Check an AI reply | /hbn/#tab=5&live=1 | 直接打开AI reviews AI的本地回复检查 |
| Data and evaluation scope | 页内展开说明 | 预计算/收敛限制、数值匹配与证明区别 |
| Inspect the mathematical evaluation | /science/ | 独立toy的保存评估，不是物理腔优化运行 |
| Explore the Blueprint case | #tour/1 | 切回同等的建筑案例 |
| All cases | #overview | 返回双卡总览 |

三个检查方向分别是 THE FIELD、THE MEASUREMENT、THE AI ANSWER。场图显示保存解随频率如何改变；窗口实验说明估计量可在物理腔没有改变时变化；回复检查流程允许复制固定toy提示、在自己选择的AI中取得答案后粘贴回本地核对。网页自身不启动该外部AI，不把用户自行取得的文本加入既有160条成绩，checker也不替代证明审查。

`Data and evaluation scope` 默认可折叠，解释未收敛的场细节、没有新仿真、固定数值参考不验证腔设计，以及数学评估独立。主页面的 #cavity 初始化与建筑catalog读取分开：即使建筑API不可用，入门内容和/hbn/链接仍可进入。真正研究页的WebGL降级、文本解析失败与unscored状态按第14–19节处理；简介页不会为缺失仿真数据伪造结果。

## 5. 建筑 Workspace：完整操作流程

### 5.1 选择任务与理解范围

工作台上方显示题目名称、家族、ID、输入条件、难度、划分及陷阱标记。右侧 `Switch task` 可以直接换题。换题会重置答案表单、证据框、临时拖拽、评分结果和参考答案显示；置信度恢复到 80%。当前实现没有自动保存草稿，离开任务前需要自行保留想要复查的答案。

读题时先确定数量的维度、物件范围和约定。房间面积、踢脚线、门套、楼板毛面积和管径属于不同问题。单位默认值只按家族提供起点，不能代替阅读题目，例如管线家族默认 `count`，但吸入总管题需要改成长度单位。`Original` 打开真实 PDF 或栅格源文件，图纸下方显示来源和许可；合成扫描还会说明尺度与页面范围被保留。

### 5.2 查看图纸和标记证据

图纸工具栏显示页面宽高与原始坐标单位。`−`、`+` 控制缩放，百分比相对于当前“适合窗口”的尺寸，而不是 PDF 物理打印比例。适合窗口按钮会重新居中整个页面。`Pan` 模式用于拖动视图，`Mark evidence` 模式用于在图上拖出矩形。鼠标移动时，底部显示原坐标位置。

证据应框选支持答案的尺寸、标签、房间边界或明确范围。按 `+ Mark a region` 会切到绘图面板、启用标框模式并聚焦画布。新框的可选说明取自 `Region note`，最长 200 个字符。列表会显示框编号、坐标、坐标空间和说明，点击对应的 `×` 删除。绘图区显示同样编号，便于对照。

如果不便拖拽，可展开 `Add a region by coordinates`，填写 X₀、Y₀、X₁、Y₁ 后点击 `Add evidence region`。四个字段都要填写，矩形宽高必须为正，坐标不能越过页面。界面最多接受 32 个框。前端的即时检查用于帮助输入，最终合法性仍由服务器 scorer 决定；例如重复框和覆盖页面超过 90% 的框仍会导致正式答案无效。

### 5.3 填写数量、置信度与假设

`Quantity` 接受数值，`Unit` 选择单位。界面提供常用的 m²、ft²、m、mm、ft、in、count；底层 JSON 还支持完整契约中的其他兼容单位。置信度滑杆从 0% 到 100%，其值会除以 100 转成 JSON 中的 `[0,1]` 数字。它表示提交者对数量达到评分正确条件的信心，不是图纸质量评级。

如果无法得到可靠数量，可勾选 `I can’t determine a reliable quantity`。此时数量输入被禁用并提交 `null`，但置信度不会自动改为零，应按真实判断调整。弃权与漏交不同：弃权有完整结构，能参与校准；缺少文件或格式错误为无效提交。

`Assumptions` 每行一条，例如“按内墙面净面积”“扣除门洞而不扣传菜口下部墙面”。界面标为 optional 是指允许没有非空条目，序列化时仍会发送必需的 `assumptions` 字段，空输入成为 `[]`。说明文本帮助人理解约定，不会被语言模型评分。

### 5.4 提交、读分与查看参考

点击 `Verify my takeoff` 后按钮显示 `Verifying…`，暂时禁用以防重复请求。成功返回时，结果卡显示总奖励、Value、Evidence、Calibration 三个加权分项；无效输入明确标为 `INVALID SUBMISSION` 并列出错误。界面用百分比显示奖励便于阅读，但这个百分比仍是契约奖励，不是准确率。

结果卡会说明证据属于 `Annotated` 还是 `Structural`。前者与参考区域匹配，后者只验证合法页内结构。证据奖励被数量分约束。若请求失败，界面显示实际错误并恢复按钮；不能将没有返回结果当成零分。

完成一次提交后，`Reveal reference solution` 变为可用。点击会显式请求参考数量、参考证据数量和假设，并标注 `HUMAN REVEAL`。它是为人的学习与演示而设计，不在正式 agent 输入中。当前界面的“提交后解锁”是操作顺序，不是对一个恶意用户隐藏答案的安全机制；公开后任何能访问该服务的客户端都可能取得参考；原始 Harbor 任务的 agent 网络是 public，不能无条件断言其不可达。新协议只配置 allowlist，实际出站阻断尚需 Docker/Modal 验证；详见第 30.6 节。

图纸变换始终从原始页坐标到屏幕坐标。缩放和平移只改变显示矩阵，保存的框仍用 `pdf_pt` 或 `image_px`。PDF 的 point 是每英寸 72 点；栅格坐标是原图像素。截图、缩略图、裁剪窗口的像素不能直接写入原页坐标。界面在添加证据时会把坐标保留到小数点后两位，因此亚像素标注的冻结版本应保持一致。

## 7. 建筑答案 JSON 契约

正式 agent 必须将一个 UTF-8 JSON 对象写入 `/workspace/answer.json`。这是 Harbor 传给独立 verifier 的交接文件，终端里说出答案或只生成图片都不满足契约。以下仅是格式示例，不是某道题的参考答案：

```json
{
  "value": 32.05,
  "unit": "m2",
  "confidence": 0.7,
  "evidence": [
    {
      "page": 0,
      "bbox": [100, 120, 240, 260],
      "space": "pdf_pt",
      "note": "用于测量的房间边界与尺寸"
    }
  ],
  "assumptions": ["按内墙面净面积"]
}
```

五个顶层字段都必须存在。`value` 是有限数字，或明确的 `null`；不能使用 `"32.05"` 字符串、布尔值或 NaN。`confidence` 是 `[0,1]` 的有限数字。`assumptions` 是字符串列表，即使没有假设也写 `[]`。`evidence` 是列表，可为空；没有框合法但没有证据奖励。

支持长度单位 `m`、`mm`、`cm`、`ft`、`in`；面积单位 `m2`、`mm2`、`cm2`、`ft2`、`in2`，及相应平方符号别名，例如 `m²`；计数用 `count`。英尺和英寸分别以单一数值表示，不支持 `ft-in` 复合文本。长度和面积不可互换，单位转换也不会替使用者判断题目究竟要的是数量还是管径。`count` 的数值必须整数化，例如 5.0 可作为整数值，5.2 不可。

每个证据框的 `page` 从零开始；原点是页面左上角，X 向右、Y 向下。`bbox` 必须恰好是四个有限数字，次序为左、上、右、下。`space` 必须等于该页声明的坐标空间，不能把 PDF point 与 PNG 像素混用。`note` 可省略；存在时必须为字符串。正式答案用矩形，不以参考标注中的 point 字段代替。

最多 32 个不同矩形。完全重复的框、负宽高、越界、页号不合法、超出页面面积 90% 的单框都会导致答案无效。限制过大框的目的，是防止“框整个页面”以低成本命中所有标签；限制重复框则防止灌水影响证据统计。这些限制是格式契约，应在生成答案前检查。

verifier 对文件设有 1 MiB 上限，并严格解析 JSON。重复键、损坏语法、非有限数字（含溢出的 `1e999`）、缺字段、布尔数值、未知单位等均得到零总奖励。建筑文件读取器与科学文件读取器是独立实现，不能把科学读取器的额外文件类型防护自动归给建筑版本。错误不会被隐式修复成“模型大概想表达的数值”，因为这种修复会破坏可重复性与评分边界。

核查来源：[严格 scorer](../blueprint_gym/scoring.py)、[文件验证器](../blueprint_gym/verify.py)、[任务说明示例](../tasks/bp-10-vector/instruction.md)、[对抗评分测试](../tests/test_scoring.py)。

## 8. 建筑评分公式、异常与弃权

建筑奖励是三个分量的加权和：

```text
reward = 0.75 × value_score
       + 0.15 × evidence_score
       + 0.10 × calibration_score
```

三个原始分量各在 `[0,1]`。结果文件中的 `components` 已经乘以权重，不能再与原始分量混加。总分 0.9 不表示回答了 90% 的题，也不表示有 90% 概率正确，它只是这一次答案满足约定的程度。

### 8.1 数量分与单位

连续测量先统一兼容单位，再计算相对于 gold 的误差。误差不超过 2% 得 1；从 2% 到 15% 线性下降；达到 15% 得 0。线性区可写为 `(0.15 − relative_error) / 0.13`。gold 为零时要求恰好为零，避免除零规则产生任意容差。存在多个获接受的参考数量时，取对应评分的最大值。

计数不是连续测量：完全相等得 1；当 gold 至少为 10 时，差一个可得 0.5；其余情况为 0。数量分不是凭“数值看起来合理”授予，例如把标高 10000 当成 m² 的面积，如果偏差巨大就得不到数量分。

### 8.2 证据分与相关性

有参考标注时，某个提交框命中参考框需 IoU 至少 0.3，或包含参考点。基础证据分由参考元素的命中比例，减去提交框中不相关框的比例，再限制为非负。提交更多无关框可能降低分数；用若干精确框覆盖所需范围通常比大量散乱框更可解释。

没有语义标注时，评分只能确认框在页内且结构合法，因此称为 structural evidence。它不能知道框中是否真的有对应房间或尺寸。即使有标注，命中房间区域也只建立范围相关性，不独立证明每条周长或缩放计算正确。

基础证据分还要乘以 `value_score`。这是一个关键设计：数量完全错误时，证据奖励为零；部分数量分也相应降低证据奖励。它使错误大数答案无法靠任意框赚到 15% 的证据部分。数值与证据联合得到信任。

### 8.3 校准与弃权

`correct` 在数量分至少 0.99 时为 1，否则为 0；校准分为 `1 − (confidence − correct)²`。正确且高置信度得较多校准分，错误却声称完全确定则校准分为零。它是一个按本题正误事件计算的 Brier 型奖励项；要评价模型整体校准仍需多次样本与适当统计。

例如，数量完全错、置信度 0.8，校准分为 0.36，总奖励仅为 0.036；数量和证据均满分、置信度 0.8，总奖励为 0.996。若合法弃权且置信度为 0，则数量和证据都为零，校准贡献为 0.10。这个上限让诚实不确定区别于高置信度乱猜，但没有把弃权当成完成任务。

### 8.4 无效、失败和重新评分

格式无效直接零总奖励，不再给予“知道自己错了”的校准分；这是无效工件与合法弃权的区别。Harbor 任务超时、未产生有效提交、运行警告和答案数值错误也不是同一层原因。完整运行的官方奖励由 Harbor 结果记录决定，不能仅因目录中存在某个评分文件就自行补一个官方分数。

人的工作台和回放重新评分调用当前 scorer，能验证保存答案在当前契约下的表现。历史官方奖励仍保留在独立字段中，不被重新评分覆盖。若未来改变容差或 gold，应生成新版本并重做评测，而不是用新规则覆盖历史成绩后仍称原实验。

## 9. Run ledger 的读取方法

`Results` 先显示两个模型的平均奖励、单次历史矩阵说明与房间案例入口；`Inspect the complete run records` 展开完整 Run ledger。平均卡片在任务数、唯一任务数或有限奖励覆盖不完整时保留不可用状态。点击 `Refresh results` 读取保存的 `data/results.json` 导出。刷新不会启动模型、补做失败题，也不会自动从原始云日志恢复缺失信息。完整记录的折叠区保留导出状态、家族/条件汇总与逐条运行；默认先显示少量可理解比较，不隐藏审计数据。

汇总表包括模型/agent、家族、条件、任务数、平均奖励、完成数、失败数和成本。逐条表包括模型/agent、任务、奖励、状态、时长与回放入口。没有被导出的回放显示 `Not exported`；无成本显示破折号，不代表免费。没有任何记录时显示等待真实记录的空态；请求失败则提供错误信息和刷新路径。

统计分母来自预定任务矩阵。某一组仍有 pending 行时，组均值保持 unavailable；结束的失败或缺失任务按零计入预定分母。正式结果不能通过只挑成功、只看有分数文件的目录来抬高均值。`graded_with_warning` 表示有官方奖励但同时有警告，它应保留警告，而不能改称没有异常的成功。

成本也遵循缺失信息不填零的原则。160 条建筑与科研正式记录中仅 38 条保留已知单次推理成本，其中建筑 35 条、科研 3 条。已知项不足以计算总推理费用，更不包含完整 Modal 基础设施费用。任务时长来自每条任务起止时间，可能包括工具执行和验证；并行任务时长相加不等于作业墙钟时长，也不能当纯模型推理延迟。

160 是两个不同任务套件、四种 agent/model 的历史 trial 总数，不表示每题三次独立模型重跑。建筑每个学习模型每题只有一条正式记录；vector、clean、scan 是三个输入条件，也不是对同一输入随机重跑三次。新增评审协议会使用新的结果目录和独立 trial 身份；在真正执行并检查结果以前，它只是一份可执行计划，不能加入现有记录册分母。

## 10. 72 条真实模型回放

建筑正式矩阵包含两个学习模型各 36 条运行，因此有 72 条真实模型回放。144 条建筑运行还包括 36 条 oracle 与 36 条 no-op 对照，不能都称为模型推理。实际可访问回放由当前结果导出中的 allowlist 决定；仓库里保留的 smoke 文件并不一定出现在当前线上记录册。

点击某行 `Inspect` 后，回放面板显示模型、任务、状态、官方奖励和警告。`Previous`、`Next` 逐步移动；`Play` 每秒前进一个保存事件，最后自动停止；再次播放可从头开始。进度滑杆可直接跳到任意事件。这里的一秒是播放节奏，不是原始执行时长，不能据此估算模型速度。

左侧时间线按每 100 步一组渲染，避免长轨迹同时产生过多 DOM。当前组之外的步骤仍可通过滑杆、Next 或 Play 到达。每步显示来源/角色、时间戳（若有）、消息、工具名称、调用参数和观察结果；较长文字默认截短并提供展开全文。`Raw step JSON` 与 `Raw exported record` 让审查者看到实际保存结构，而不是只看编辑后的故事。

`The submitted answer` 区域展示保存数量、单位、置信度及原始答案 JSON。`Open source task` 回到对应建筑任务，会按工作台正常换题规则重置手工表单；这不是把保存答案复制成可编辑模型会话。`Show saved evidence on source` 将有效证据框叠加到真实图纸，同时列出坐标和说明，框仍保持模型提交的原始空间。

`Recheck saved answer` 把保存 JSON 原样送到当前 verifier。它不补单位、不修框、不替模型改置信度；界面明确区分当前重新评分与历史官方奖励。如果答案缺失、任务不在目录、字段不合法、框重复或越界，重新评分按钮禁用，并解释原因。保留无效答案是审计的一部分，不应为了让按钮可用而悄悄修正。

回放离开记录册时停止计时器，关闭面板会使旧请求失效。快速点开其他记录时，上一条迟到的响应不能覆盖新记录。若没有事件但有答案或评分，页面会说明“没有导出步骤”，下方评分证据仍可检查；没有步骤不等同于有一段隐形推理。

一个保留的 smoke 示例 `smoke-no-snapshot-bp-10-vector` 有 12 步：检查 PDF、打开渲染页、写出答案等均来自记录。它提交 5 个阀门、置信度 0.9、7 个框，奖励为 0.956142857。该单题是执行链可用的证据，不能代替完整任务集合表现。

## 11. 建筑结果与可以得出的结论

正式建筑矩阵已结束：36 题 × 四个 agent/model，共 144 条已评分记录，零 pending。两条 DeepSeek 警告仍在分母内。正式 oracle 是 `full-oracle-verified`；被中断的早期 `full-oracle`、smoke 和重复运行归为历史诊断，不混入最终矩阵。

| agent / 模型 | 预定任务数 | 平均 verifier 奖励 | 解释 |
| --- | ---: | ---: | --- |
| Oracle | 36 | 1.000000 | privileged gold reference：写入预置参考答案，检查奖励可达与评分管线 |
| No-op | 36 | 0.000000 | 不提交有效答案的对照 |
| DeepSeek | 36 | 0.3924090871 | 包含两条警告的全任务均值 |
| Kimi | 36 | 0.8073081063 | 同一 36 题任务矩阵的均值 |

总体均值按任务行聚合，不把大小不同的家族均值不加权平均。房间面积每条件两题、管线每条件三题，直接平均各家族会改变题目权重。报告还保留家族 × 条件细表，便于定位问题，但每个单元只有两三题，不适合据此做广泛模型能力排名。

Oracle 的 solution 脚本已经包含参考答案；它没有在与学习模型相同的信息权限下重新解图。其 1.0 是有效的正对照，却不是“公平的完美求解策略”，不能单独证明可学习的稳定性能差距。Kimi 在这份历史矩阵上高于 DeepSeek 是可观察比较；若要满足评审的 repeated runs 要求，还需固定任务、预算与工具，实际进行三次独立尝试并报告波动、失败与 warning。

报告中的一个 DeepSeek 健身房合成扫描例子数量正确，整体奖励仍只有 0.857160，因为证据与置信度不是满分。同场景清晰图的记录数量分只有约 0.524735，总奖励约 0.466297。两个例子说明应该同时看数量、证据和轨迹；它们不能证明扫描比清晰图更容易，也不能据两条轨迹推断确定因果。

陷阱例子同样需要克制描述。报告记录的 `full-deepseek-bp-09-clean` 提交 303.0 m²，数量分为零，奖励 0.061560，说明该次陷阱数量失败。它并没有独立证明模型将标高认成面积。另一段录制使用 `full-deepseek-bp-09-scan`，该条缺少保存提交且官方为零；不能给它编造错误答案或阅读过程。

本结果能支持“任务可运行、评分可复现、真实基线存在、工具轨迹可检查”。它不支持“工业应用已验证”“真实扫描性能已证明”“holdout 从未被看过”“模型权重得到了训练”。如果要开展后训练，应预先设计新的数据划分、冻结评估集并报告训练前后差异；当前项目没有这份实验。

## 12. Boundary lab：通用数学 toy

Boundary lab 的目标是让一个容易被背景分解误导的数学步骤变得可检查。它独立定义以下对象，使用在原点解析的主分支：

```text
q(u) = (1 − u)^(3/2)
f(u) = A + q(u)
E(u,v) = g[c + f(u) + f(v)]
H(z) = −½[log(1 − z) + z]
F(u,v) = H(E(u,v))
a_ii = [u^i v^i] F(u,v)
C_i = [u^i] q(u)
```

要找的是 `a_ii / C_i²` 在 i 趋于无穷时的极限。关键在于边界 u=v=1 时 q 消失，但 f 的常数 A 不消失，所以完整背景是 `E_* = g(c+2A)`。正确极限为：

```text
L(g,c,A) = g² / {2[1 − g(c+2A)]²}
```

历史备选写成 `g² / {2(1−gc)²}`，一般遗漏 2A 的贡献。只在 A=0 等非区分情形，两者会重合。证明不仅写了局部混合项，还说明解析域、其他奇点排除以及高阶项为何不会贡献同阶主项。对精确系数得到余项 `O(i^−3)`；这个渐近结论不能直接套在有限网格浮点输出上。

一项足够但并非必要的参数条件是 `|g|(|c|+2|A|+2·2^(3/2)) < 1`。后端通过有理数不等式判断，浮点显示的 B 只用于阅读。这能保证闭双圆盘内对数分支无额外零点。无法满足该充分条件不必然说明数学上绝无其他有效参数域，但本项目的验证契约不延伸到未经检查的范围。

### 12.1 页面中的完整操作

页面顶部给出工作要求和保存模型成绩；`Refresh saved results` 只重新读取保存成绩。`Validated case` 选择 a-01 至 a-04，显示 g、c、A、是否 A=0 对照以及已保存的域条件。每次切换案例，参考公式、数值、系数和证明都重新藏在显式 reveal 门后。

按 `Reveal saved validation` 才读取该案例的详细保存输出。成功后显示完整边界参考、精确有理数、历史备选、相对差异和解释。A=0 的提示明确说明该例无法区分公式，不应把备选的吻合称为“错误公式通过检验”。加载失败会显示错误，并允许再次请求；它不会用硬编码的成功数值替代失败读取。

图表可选 `M=1024` 或 `M=512`，以及系数比值或相对误差视图。三个采样阶数是 i=80、100、120。聚焦或悬停点可查看原始数值，方向键在点之间移动。表格同时显示所选网格与另一网格，便于非视觉核查。连接线只帮助阅读，不表示额外测量点。

下方折叠区分别提供局限、方法/来源哈希、独立证明和原始保存 JSON。页面切换不会重新运行 FFT，也不能修改四组参数。需要实验新参数时应通过独立本地计算、验证和版本记录完成，而不是把当前图当作任意参数仿真器。

### 12.2 数值检查究竟建立了什么

系数通过直接采样定义中的 E 与 F，再做二维 FFT 得到；解析参考只在之后用于误差比较。半径规则是 `r=exp(−4/M)`，系数按 `M²r^(2i)` 归一化，C_i 通过二项式递推得到。因此计算不是把解析答案画成曲线。

保存的四例在选定阶数满足 1e−3 一致性目标，最大观察相对误差约 1.3e−4。固定网格时，误差在所展示阶数可能增大；这不是有限数值序列收敛的证明。比较 M=512 与 1024 同时改变半径，反映混叠和舍入的联合敏感性。epsilon 估计量是诊断尺度，不是严格误差界或置信区间。精确解析证明、数值一致性和原始科研应用是三件事。

一个可精确定位的失败是 `science-kimi-four / science-a-03`：保存答案为 0.0057988165680473375、置信度 1、奖励 0，运行状态为 completed，不是超时。其 rationale 将 `E=e0+g(h(u)+h(v))` 中的常数取成 `E(0,0)=g(c+2A+2)=0.35`；由于 `h(0)=1`，这一写法重复计算了常数偏移。正确展开的常数应为 `g(c+2A)=0.21`，参考极限 0.003925652940233937，保存答案相对偏大约 47.7%。这是由真实提交直接支持的具体代数错误；与 hBN 弹窗中另一段历史错误值 0.002318354554951627 不同，不能混成同一条模型试验。

## 14. Cavity 研究页的总览与显示规则

Cavity 的完整研究页位于 /hbn/，历史文档也称 Nanocavity Lab；页面集成五个离线交互模块。源材料保存在 `demo/hbn_live/`；修订版由 `hbn_demo/build.py` 读取固定哈希的原始 HTML，注入界面、数值检查、降级和说明代码，输出 `hbn_demo/index.html`。维护者应编辑构建输入并重建，不在约 9.5 MB 的生成页里临时改字后忘记来源。

页面品牌为 Cavity，并提供 All cases 回 /#overview、Blueprint 进入 /#tour/1、About Cavity 回 /#cavity。由总览选择 Cavity 时可先读入门；直接打开 /hbn/ 的访问者也能用这些链接了解案例或切换到 Blueprint。导航改变的是可发现性，不会改变原始场数据、checker 或评分。

页面顶部的五个标签按顺序是 `Cavity in 3D`、`Square cavity (COMSOL)`、`Mode map`、`Pick your box`、`AI reviews AI`。`Plot appearance` 切换绘图色彩；浅色产品外壳仍维持清晰的导航。桌面以画布和侧栏并排，窄屏改成纵向排列，顶部标签可以横向滚动，控件具有较大的触摸目标。

## 15. 模块一：RCWA 腔场示意

`Cavity in 3D` 将二维 RCWA 腔场组织成可旋转的三维示意。三维观察方式帮助理解层与截面，并不把二维解变成完整三维求解。数据包含 1440–1580 cm⁻¹、步长 2 cm⁻¹ 的 71 个频率切片，选择频率时读取已嵌入数组，动画只是复场相位随时间变化的可视化。

`Play/Pause` 控制波动动画；`Re E_z (wave)` 显示垂直电场实部，可观察正负相位；`|E| (field magnitude)` 显示场幅，不能称其为强度。`speed` 从 0.1 到 2 调节动画速度，不改变物理模型或场数组。`Auto-rotate` 控制相机旋转，不是物理旋转激励。

频率滑杆按离散切片选择，`Sweep` 自动遍历已保存频率；也可点击谱图选择附近频点。`common brightness scale` 默认开启，使不同频率用公共亮度尺度，便于比较场幅变化。关闭后局部视觉对比增强，但不能再仅凭颜色深浅跨频率比较绝对强弱。任何截屏都应记录是否使用公共尺度。

界面写明 801 阶网格最大值在 1496 cm⁻¹，论文参考为 1497 cm⁻¹。这个 1 cm⁻¹ 差异不能被叫作定量验证：频率网格为 2 cm⁻¹，而且更高阶场收敛没有建立。已有收敛摘要显示 801→1201→1601→2001 的局部场相对 L2 变化仍约 20–33%，积分量也有变化。与旧 801 阶结果重合只证明相同离散化可重复，不证明接近真解。

正确的演示方式是先用公共尺度扫频定位结构变化，再展示网格最大值和收敛限制。不能选择最接近论文的一张图，隐藏非收敛说明，再称“复现成功”。该模块适合解释场形、相位与离散采样，尚不承担精确峰位、局部增强或误差界的证明。

## 16. 模块二：固定探针 COMSOL 方腔

`Square cavity (COMSOL)` 展示三维 COMSOL 驱动场的预计算切片。几何说明包括 SiO₂、10 nm Au 方孔、25 nm h¹¹BN、位于上方 5 nm 的 Pt 探针，以及 45° p 偏振入射。模型是 y≥0 的半模型，界面用剖开方式展示内部结构。它显示总场相对于入射场的量，不是探针横向扫描获得的 s-SNOM 图。

`Cavity width` 用按钮选择可用宽度；切宽度后默认选该宽度的共振频率。`Frequency` 在已保存共振和离共振切片间切换，标签给出 cm⁻¹ 与 resonance/off 状态。用户只能选择存在的数据切片，按钮不会要求后端求解新宽度。具体为 w=200 nm 的 1495.5 cm⁻¹ 共振与 1444.0/1548.0 cm⁻¹ 离共振，以及 w=120 nm 的 1536.1 cm⁻¹ 共振与 1572.0 cm⁻¹ 离共振。

`Top surface` 可切换 hBN 上方 1 nm 的 Re E_z 或 hBN 中部的 |E|；`Cross-section (y=0)` 可切换波动实部与场幅；`Play/Pause` 控制相位动画。侧栏同时显示腔内平均 |E|² 相对 |E₀|² 及一个倍数。这个倍数以该宽度最弱离共振采样为分母，不是与自由空间任意点或所有可能频率比较的普遍增强倍数。

## 17. 模块三：宽度–频率 Mode map

`Mode map` 将 11 个宽度（60–260 nm）的光谱排成二维热图，下方给当前宽度的谱线，右侧给峰值、Q、参考偏差与所有宽度表格。横轴为波数频率，纵轴为腔宽。它的目的在于比较模式脊线和观测量，而不是把热图当作空间显微照片。

`NF₄ signal` 与 `hBN absorption` 切换热图所用量，同时保留另一条谱线作对照。NF₄ 的构造来自三个探针高度的复幅二次插值，再沿 tapping 路径计算 |r|² 的第四谐波幅值。它是模型代理量，不能暗示与实验论文的检测量完全等价。吸收量是 hBN 域内吸收功率，在最近探针高度取值。二者峰位可以不同，不能随意互换。

每个宽度分别归一化到自身最大值。热图适合比较一个宽度的谱形或峰位迁移，不支持比较不同宽度的绝对信号强度。`smooth` 只在线性插值宽度方向让显示连续；`per width` 把真实宽度画成 ±10 nm 条带。插值不创造新仿真，悬停实际会吸附到最近的已计算宽度，下面的谱线仍来自该宽度数据。

图例按钮分别开关本工作脊线、论文数字化脊线和悬空 25 nm 薄板的 `λ_A0/2=w` 参考。悬停热图读取宽度，点击固定；上下方向键逐个切换宽度，表格行也可点击选择。谱线悬停给出频率及两个归一化量。离开悬停位置后恢复已固定的宽度，侧栏标明 hover/pinned，避免临时读取被误认作永久选择。

空心标记表示峰值不位于密集 1.5 cm⁻¹ 扫频内部；某些大宽度只有粗 8 cm⁻¹ 网格或峰在扫描边缘，f₀ 与 Q 不确定。斜线区表示没有数据，不能把空白解释成零信号。谱线图中的基线和半高宽线段帮助理解局部 Q 算法，不能消除采样不足。

论文参考脊线取自论文 Fig. 2b 的仿真部分而不是实验测量部分。两次数字化之间的差异只是重复数字化差异，总参考不确定度仍未知。悬空薄板 λ_A0 指南又属于不同几何和近似模型；偏差显示出来正是为了避免“图上几条线接近就说明等价”的推断。

## 18. 模块四：Q 与拟合窗口敏感性

`Pick your box` 是整个科研演示中最直接的敏感性实验：同一条 w=120 nm 吸收谱，完整窗口得到 Q≈52.719497，而 1522–1554 cm⁻¹ 窄窗得到 Q≈96.393006。数据没有重新计算，只改变了截取窗口和基线估计。这说明估计器依赖选择，不说明窄窗更接近真实 Q。

上方谱图中可拖动窗口边界；`Main table: full range` 恢复完整采样范围，`Mesh section: 1522–1554` 选择报告中窄窗。侧栏更新峰位、半高宽与 Q，并显示窗口依赖提醒。修订页对宽度不超过 32 cm⁻¹ 的窗口明确标出窄窗/窗口受限提醒；其他部分窗口仍说明基线与边缘采样影响。此提示阈值是界面警示策略，不是所有光谱通用的有效性定理。

Q 的定义在这里是 `f₀/FWHM`。算法以窗口端点连线作基线，从扣基线后的峰确定半高交点，并用线性插值估宽。缩窄窗口时，端点可能仍处在峰肩上，基线被抬高，半高宽被压窄，Q 随之增大。即使无噪声、单峰、理想 Lorentzian，也能出现这一效应，所以“曲线更漂亮”“更接近文献”不是选窗的充分理由。

下方 Q(w) 图将相同逻辑推广到 11 个宽度。`Full computed range` 使用完整计算范围；`±Δ around each peak` 以各自峰为中心取窗口，Δ 滑杆在 8–80 cm⁻¹ 间以 1 cm⁻¹ 步长调节半窗；`Fixed window` 对所有宽度使用同一上下界，lo/hi 滑杆以 0.5 cm⁻¹ 步长控制端点，范围来自现有谱线的频率上下限。端点会保持至少 1 cm⁻¹ 的顺序间隔，但这仅保证界面数值有效，不保证物理半高宽可辨识。

`Δ-range band` 控制显示一组窗口选择带来的范围带。它是参数敏感性区间，不是统计置信区间，不包括所有模型误差，也不能用作测量不确定度。可悬停宽度读取估计值，并同时观察论文 Q(w) 比较；存在无效或边缘受限窗口时，应保留对应提示或缺失值。

来源模块还指出，过窄 Δ（例如 ≤12 cm⁻¹）可能使线宽缺乏意义。全窗也不自动是真值，它仍受背景选择、非对称峰、采样网格及模型近似影响。推荐演示顺序是展示全窗、切窄窗、返回全窗，然后解释变化机制；不要以“挑到了更高 Q”作为实验成功结尾。

核查来源：Q 宽度模块（开发归档路径：`../demo/hbn_live/modules/q_widths/README.md`）、独立物理审查及 Lorentzian 分析（开发归档路径：`hbn-integration/PHYSICS_REVIEW.md`）、窗口提醒实现（开发归档路径：`../hbn_demo/build.py`）、浏览器 Q 检查（开发归档路径：`../hbn_demo/check_browser.py`）。

## 19. 模块五：AI reviews AI 与严格回复检查

### 19.1 历史故事和可计算 toy

`AI reviews AI` 左侧逐步展示提供方报告的研究历史。`Next` 展开下一条，`Restart` 重置展开状态及计算/揭示状态。这里的日期、角色与叙述来自被提供的历史材料，当前产品没有重新核查原始研究服务器、完整原帖或原模型过程。独立 toy 证明可以成立，但不因此证明所有历史归因。

右侧提供 g、c、A 三个滑杆，范围分别为 −0.3–0.3、−2–2、−1–3，步长分别为 0.005、0.05、0.05。三个预设是标准非零背景、A=0 对照以及接近边界的参数。`Compute the coefficients` 在浏览器本地计算 toy 系数曲线，`Reveal the analytic reference` 标明两条公式的身份。它与 `/science/` 的四组保存 FFT 检查不同：本模块确实可对当前滑杆参数做本地数值计算，但没有模型推理。

状态区显示解析展开条件检查；达到无效域时显示不能展开，靠近边界时提示收敛慢。曲线图涵盖 i=10–300，标出 i=300 的结果；未达到内部收敛判据会显示 series not converged。即使图上逼近参考线，也仍应阅读解析证明和方法范围，不能把有限曲线当作原始科研定理的完整证明。

### 19.2 弹窗的每个操作

`Local reply checker` 打开弹窗。顶部 `Solve the problem` 与 `Review the colleague’s step` 切换两种固定 prompt，参数都明确包含检查点 `(0.07,−0.4,1.7)`。`Copy prompt` 使用剪贴板；权限不允许时退回选择文字，用户可自行复制。复制本身不把内容发到模型服务，产品没有 API key 输入框或自动推理通道。

用户把已有回复粘入文本区，再点 `Check reply`。页面只运行本地 JavaScript。弹窗还保留两个公式的观众手工计数按钮 `① +1`、`② +1` 与 reset；这是现场举手记录，保存在页面内存，不能当模型评测数据。下方九条历史试验只有提供方的两行摘要，不能与正式 Harbor 结果合并。

手机上 `Close (Esc)` 常驻弹层顶部，便于长文本滚动时关闭；也可按 Escape 或点击遮罩。弹窗打开时背景设为 inert，Tab 焦点在弹窗内循环，关闭后返回打开按钮。输入文字时全局数字快捷键被屏蔽。这样操作焦点与背景标签不会争夺键盘事件。

### 19.3 严格格式与返回状态

一次输入最多 100,000 个字符，只允许一个无歧义的 ANSWER 或 VERDICT 字段。支持 Unicode 负号与部分全角英文字母/冒号归一化。字段重复、同时出现答案与判断、含糊文本、无法解析的公式、数字后附额外词语，都进入未评分，而不是从整段文字抓取一个“看起来正确”的数字。

推荐数值格式如下：

```text
ANSWER: 0.003925652940233937
```

也可按 prompt 的完整一行格式：

```text
ANSWER: L = g^2 / (2*(1-g*(c+2*A))^2) ; L(0.07, -0.4, 1.7) = 3.925652940233937e-3
```

完整格式中左侧公式只是保留供人阅读；检查器不解析或证明它。科学记数可用 e/E 或乘 10 的指数写法，数值必须有限且只有一个。固定正确值为 0.003925652940233937，历史错误值约 0.002318354554951627。匹配阈值是相对误差严格小于 0.001。

| 状态 | 触发条件 | 正确解读 |
| --- | --- | --- |
| `numeric_match` | 数值接近固定参考 | 数值一致，公式与证明仍需人工检查 |
| `historical_value` | 数值接近历史错误公式 | 命中了已知错误数值 |
| `numeric_mismatch` | 有效有限数值但不匹配参考 | 该固定参数的数值不一致 |
| `incorrect_verdict` | 恰好 `VERDICT: CORRECT` | 接受了给定的错误推导步骤 |
| `manual_review` | 明确 `VERDICT: INCORRECT`，可附 L=公式 | 识别到拒绝判断，推导质量留待人检查 |
| `unscored` | 格式重复、含糊、溢出或无法解析 | 没有评分，不能当作成功或失败证明 |

`VERDICT: INCORRECT — L = …` 进入人工复核，而不是“证明正确”的绿色满分。包含 `c+2A` 字样也不足以证明推导；检查器不执行 eval，不运行粘贴代码。`hbn_demo/grade.py` 调用同一份 `grade.js`，因此 CLI 与网页遵循相同规则：退出码 0 为数值匹配，1 为明确数值/判断不一致，2 为未评分或人工复核。

### 19.4 九条摘要与因果解释的界限

九条摘要涉及 Haiku、Sonnet、Opus、Fable 等标签，均报告成功，但没有完整轨迹与受控比较。它们不能称为官方 Harbor 得分，不能算模型失败率，不能与 8 条真实科学模型尝试混成一个统一分母。历史错误可能受锚定影响，这只是待检验解释；没有因果实验时，不能声称“已证明是锚定而非知识不足”。

建筑 agent 镜像的主要图纸库固定为 PyMuPDF 1.26.6、Pillow 12.0.0、NumPy 2.2.6、Shapely 2.1.2、OpenCV headless 4.12.0.88；主机依赖锁另外固定 Harbor、Modal、FastAPI、Playwright 等版本。两套环境服务不同用途，复现时要使用对应的锁和 Dockerfile，而不是把主机 pip 列表复制到 agent 后声称环境相同。

可选工具并不等于推荐每题全用。矢量 PDF 可以先提取文本与对象，再按需渲染局部；栅格图可能需要 OCR 与视觉核对；计数可能依赖标签定位，面积依赖几何和尺度。评估实际策略时，回放中的 tool call、参数和 observation 才能说明它做过什么。

## 21. 目录、数据流与 API

项目目录分开了正式任务、人的工作台、保存结果、科研侧项目和部署准备。这个分离不是仅为整洁：正式 agent 不应看到 gold，站点静态源不应携带后端秘密，研究展示也不应把整份原始项目顺带上传。

```text
tasks/<id>/                 建筑 Harbor 任务
  instruction.md            工作要求与答案契约
  task.toml                 schema、资源与工件声明
  environment/              中性图纸与 agent Dockerfile
  tests/                    trusted gold、scorer、verify、test.sh
  solution/solve.sh          oracle，位于 agent 上下文之外
blueprint_gym/              共用 scorer、verify、人的 API
web/                       建筑前端 index/style/app/replay
data/                      来源、目录、预览、授权、脱敏结果/回放
configs/                   Modal 与本地 Docker Harbor 作业
scripts/                   构建、启动、运行管理、导出、归档、录制
science_demo/              独立 toy、证明、验证、任务、API 与前端
demo/hbn_live/             保持原样的筛选研究来源
hbn_demo/                  修订构建输入、生成页、授权与检查器
hosting/                   stage、哈希验证、公开 Site/受保护后端部署与测试
video/                     新影片可编辑源、真实录屏和素材来源
docs/                      决策、审查、验证与本手册
dist/                      本地交付工件；不是全部随 Git 分发
runs/                      原始运行记录；保持忽略与私有
.cache/                    临时预览、测试与工具缓存
```

正式评测的数据流为：任务包 → Harbor 建立 agent 容器 → OpenCode/模型使用工具 → `answer.json` → 单独 verifier 容器 → `reward.txt` 与 `breakdown.json` → 原始运行记录 → 脱敏导出 → 网页记录册。人的工作台走另一条短路径：目录/图纸 → 用户表单 → 同一评分函数 → 分项反馈。它没有中间的模型调用。

科研保存页读取验证元数据，只有显式 reveal 才返回本案例的详细参考、证明和数值。hBN 页面经公开 Site 的固定代理提供，源工件位于受保护后端；加载后主要交互在浏览器完成。窗口重算与 toy 系数计算无需回传研究数组。

| 接口 | 方法 | 用途和返回边界 |
| --- | --- | --- |
| `/api/tasks` | GET | 公开目录字段，不含 gold |
| `/api/tasks/{id}` | GET | 已存在任务的元数据 |
| `/api/tasks/{id}/image` | GET | 固定任务预览 PNG |
| `/api/tasks/{id}/drawing` | GET | 固定文件名的源图 |
| `/api/tasks/{id}/score` | POST | 读取严格答案对象，返回实际评分 |
| `/api/tasks/{id}/solution` | POST | 必须 `reveal:true`，人的显式参考展示 |
| `/api/results` | GET | 已审查导出或明确 pending/unavailable |
| `/api/runs/{id}` | GET | 仅当前导出引用的脱敏回放 |
| `/science/api/...` | GET/POST 按科学 API 定义 | 元数据、保存运行与显式案例 reveal |
| `/hbn/` | GET/HEAD | 唯一获审查自包含研究页面 |

核心评分请求体超过 1 MiB 返回 413；严格 JSON 解析失败返回 400。不存在的任务、未获导出许可的 run ID、越界路径或不支持的图纸名返回 404。保存数据尚不可用时采用明确 503 或 unavailable 状态，具体取决于端点。API 不允许通过文件路径参数任意读取项目目录。

## 22. 本地启动、复现与验证

### 22.1 最小的人类工作台启动

从仓库根目录使用 Python 3.12 和锁定依赖。新机器可先创建虚拟环境；已有专用虚拟环境时直接复用，不应改动共享机器其他项目环境。

```sh
python3.12 -m venv .venv
nice -n 15 env OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python -m pip install -r requirements.lock
bash scripts/serve.sh
```

脚本默认在 `127.0.0.1:8430` 启动单 worker Uvicorn，内部已经设置 nice15 与数值线程1。打开本地根地址即可使用建筑页，后接 `/science/` 或 `/hbn/` 访问科研入口。不要将监听地址随意改成公网所有网卡；本地开发服务、公开 Site 与要求服务器凭据的上游后端不是同一安全边界。

集成 worktree 可复用主项目虚拟环境并选用空闲的 8432 端口。应在当前 worktree 目录运行，使模块来源正确：

```sh
nice -n 15 env OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python \
  -m uvicorn blueprint_gym.server:app --host 127.0.0.1 --port 8432 --workers 1
```

端口占用时先检查对应进程的命令与工作目录，不能根据旧交接 PID 直接终止进程。共享机器上其他项目、GPU、模型服务、会话和端口均不属于本手册授权范围。

### 22.2 仅离线评分

将自己的合法答案保存成项目内文件后，可以不启动 HTTP 服务直接评分：

```sh
nice -n 15 env OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python -m blueprint_gym.verify \
  --gold tasks/bp-10-vector/tests/gold.json \
  --answer answer.json --output-dir .cache/local-verifier
```

输出目录包含 reward 与 breakdown。该命令需要读 trusted gold，因此是主机侧复核，不应放进 agent 解题上下文。它不会启动 Harbor、调用模型或申请云容器。失败时先检查文件是否普通 UTF-8 JSON、字段是否完整、框是否使用正确坐标系，再讨论测量本身。

### 22.3 确定性构建与冻结

建筑任务生成器消费已提交的规范化 PDF 与整理记录，并检查源哈希；它不重新下载原始图纸。科学生成器消费固定参数。hBN 构建器检查原始 HTML 的精确哈希及每个预期替换次数，不符合时中止，避免来源变了仍默默套补丁。

```sh
nice -n 15 env OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python hbn_demo/build.py
```

建筑/科学任务在正式评测时已经冻结。修改 generator 后生成的新包必须作为新版本检查，不能在运行进行中重建原任务，不能让历史结果对应的 drawing/gold/instruction 悄悄变更。hBN 显示修订不应改变这些已评分任务。

### 22.4 本地测试与浏览器检查

```sh
nice -n 15 env OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python -m pytest -q tests hosting science_demo/test_evaluation.py
nice -n 15 node --test hbn_demo/test_grade.cjs
nice -n 15 node hosting/test_proxy.mjs
nice -n 15 node hosting/test_worker.mjs hosting/.site-build-refresh/dist/server/index.js
nice -n 15 env OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv/bin/python hbn_demo/check_browser.py
```

浏览器检查脚本使用本机固定 Chromium 路径和软件 WebGL。迁移机器时应配置实际存在的浏览器，不应期待主机缓存路径通用。该脚本覆盖 1440px 桌面、390px 手机、390px 无 WebGL三组条件的五个标签，共 15 个组合，并检查无横向溢出、有效画布尺寸、无 JavaScript 错误和无外网请求。它还检查回复含糊时未评分、文本区数字不切标签、关闭弹窗恢复焦点和 Q 全/窄窗读数。

### 23.1 已授权的匿名观众与独立后端秘密

用户已明确回复“包含，公开现有完整演示与 hBN 数据”。此授权覆盖现有完整产品、保存模型结果/回放、人工评分/参考展示、独立 toy 与筛选后的 hBN 数据，观众是无需登录或密码的匿名访问者。公开入口为 `https://blueprint-takeoff-lab.bronze-crane-2444.chatgpt.site/`。这取代早期 owner-private 观众限制，不需要反复为同一公开范围重新确认。

### 23.3 CSP、媒体与来源一致性

工作台使用同源脚本策略。hBN 的 200 响应根据实际内联脚本内容计算 SHA-256 CSP，允许确切脚本运行；禁止内联事件属性，`connect-src 'none'` 阻止该研究页脚本外联，图片仅允许 data，并禁止 framing、base URI 与表单提交。公开观众不需要放宽这些限制，也不代表浏览器会将研究数组发送给模型 API。

播放器通过同源媒体路径加载影片、字幕与海报，用户控制播放和声音。影片旁边保留音乐与图示署名；外部出处链接仅在访问者主动打开时跳转，不是播放需要调用的 AI 或求解服务。hBN 中修改任一脚本字符都要更新 CSP 哈希；不能以全站 unsafe-inline 解决版本混合问题。

历史平台曾插入已识别 edge 脚本，原 CSP 阻止了其运行；剔除明确的那个块后才验证原页面一致。该历史处理不是忽略任意远端字节变化的许可。新的部署仍需核对原始响应、允许的平台变换和对应清单。

### 23.4 Stage 与公开路由是不同交付范围

`hosting/stage.py` 通过 allowlist 复制固定后端/前端、经过筛选的目录、图纸/gold、导出结果与回放、toy 和 hBN。新增 `--audience public` 检查公共展示授权；hBN 还要有 `--reviewed-hbn-sha256`。媒体审查必须精确列出影片、字幕、海报与中文 PDF 四项，并逐一核对来源 SHA-256，复制到固定 public_delivery 名称。未知路径、符号链接、重复任务、变化的哈希或已存在输出目录会被拒绝。

Stage 还包含评分器需要的服务器文件，不能把整个目录映射为任意匿名静态文件树。公开的是审核过的功能和路由；Worker 只选择前端资源与固定代理，媒体与 PDF 只通过限定名字访问。先校验 stage、测试应用，再校验后部署；源文件变化后要重建审查清单，不能沿用旧字节哈希。

哈希能说明“交付字节与审查字节相同”，不证明参考答案科学正确、网络策略已强制执行或第三方许可自动满足。电影与文档的哈希由各自 delivery manifest 维护，避免将更新的 PDF 与旧成片清单混在一起。

### 23.5 授权扩展与仍然独立的事项

早期建筑授权覆盖指定来源与专家参考；科学授权随后允许独立 toy 的展示与 Verda/Modal 验证；再后允许筛选的未发表 hBN 数据在私有站点展示；本轮明确扩展到现有完整演示及 hBN 数据的匿名公开。应把后来的明确授权应用于当前工作，而不让早期“待授权”或 owner-private 文本继续阻挡同一范围。

这次公开授权不自动意味着新增昂贵 RCWA/COMSOL 求解、GPU 训练、把原始研究项目发给模型 API 或公开服务器凭据。原始大体积模型、未选入演示的研究日志和环境文件也不因公开产品而全部进入 stage。第三方音乐、论文图示与图纸各自按许可署名；用户拥有的 hBN 数据授权不会替代第三方许可。

### 23.6 公开答案对未来 agent 评估的影响

展示功能主动公开参考和真实提交，因此未来能上网的 agent 可能取得答案。历史 smoke/full/direct Docker 配置仍使用 `network_mode="public"`，不能无条件说“正式 agent 永远看不到 gold”。文件构建上下文中没有 gold 只能证明一层隔离，不能证明公开网络答案不可达。

新协议复制独立任务并把运行 agent 限制为 `inference.verda.com`，verifier 保持 no-network；但目前只完成代码、schema 与离线检查，Docker/Modal 的实际出站控制、阻断目标及推理连通性仍待执行验证。即使网络限制正确，模型先前记忆也不能被排除。这是新的网络策略版本，必须和历史 160 条记录分开。具体来源哈希与拒绝行为见第 30.6 节。

### 26.3 维护时保持的契约

首先保持原始证据：历史运行保留原状态、警告、未知项和提交，不能为了演示补写。其次保持版本对应：更新 UI 可不改分数，更新 scorer/gold 则必须明确新版本与重评。再者保持来源分离：原始 hBN 输入不直接改，修订由 build 产生并记哈希。最后保持最小交付：只 stage 必需文件，不上传整份 home、cache、runs 或原研究目录。

## 27. 常见故障与问答

**目录显示 unavailable，是否所有任务消失了？** 先区分网络/API 读取失败与目录为空。点击 Try again，确认本地服务进程及目录文件来自当前工作树。公共站点则核对匿名部署登记与后端状态。不要通过直接开放整个 data 目录来“修复”目录读取。

**图纸加载不出来，但 Original 可以打开。** 这通常说明预览 PNG 路径或文件有问题。可以从原件核查图纸，重新选择任务重试；提交仍应使用目录声明的原始坐标系。不能拿浏览器 PDF 截图像素当作 pdf_pt。

**换题后证据没了。** 这是当前状态重置行为。界面没有草稿自动保存；先记录答案再换题。刷新页面也不保证恢复先前手工输入。

**框可以在前端加入，提交却无效。** 前端只做即时几何/数量限制，后端还检查重复、超大、页号、空间与字段类型。读取 score errors，按严格契约修正自己的答案；如果是保存模型答案，保留原件，不替模型修后再冒充历史结果。

**我写对了数，为什么没有满分？** 证据命中与置信度另占 25%。检查 Value、Evidence、Calibration 的加权贡献；还应确认单位相容以及参考范围。数量满分不能自动替代相关证据。

**我弃权了为什么仍有分？** 合法弃权可获最多 0.10 校准贡献，这是契约设计。它没有数量/证据分，和缺失文件零分不同。

**网页里看到 80.73%，是不是 Kimi 准确率 80.73%？** 不是。它是 0.807308 平均奖励按百分数展示，包含数量、证据与校准。计算准确率需要另定义正确事件并统计，不能改标签了事。

**为什么成本是破折号？** 提供方/框架没有完整成本元数据。未知不等于零，也不能根据有成本的 38 条推算所有运行费用。

**回放点击 Play 是否收费？** 不会启动模型，它按保存事件播放。重新评分只调用 deterministic scorer。只有明确执行新的 Harbor 模型命令才会进入推理资源路径。

**回放没有答案或 Recheck 禁用怎么办？** 阅读 unavailable/invalid 原因。可能原作业没有提交，或者导出没有保留工件。不要从参考答案填充缺失模型提交，否则破坏真实证据。

**科学页点 reveal 是否重新计算？** Boundary lab 只读取保存验证；Cavity 的 Compute 才执行本地 toy 系数计算。两种按钮名称相似，但计算来源不同。

**A=0 时两个公式一样，是否说明历史公式正确？** 只能说明这个对照无区分力。需要非零 A 案例和解析推导才能检验漏掉边界常数的问题。

**科研页面黑屏或没有 3D。** 查看是否显示 WebGL 降级提示；二维 Mode map、Q 和 toy 应仍可用。如果整个页面停止，检查实际加载的是否修订 `hbn_demo/index.html`，而非原始独立模块 app.html/test_core.html。这些原始开发入口依赖未随筛选带来的 vendor 文件，不是完整交付入口。

**手机上 3D 难拖动。** 先用放大/缩小/复位按钮，允许页面正常滚动。侧栏已改成纵向布局，顶部标签可横向滚动。不要缩成桌面整页来勉强找到控件；390px 是明确检查宽度，但所有浏览器组合并未逐一认证。

**Q 窄窗更接近论文，能直接选它吗？** 不能仅靠接近参考决定。应同时保留全窗、窄窗、基线与边缘提示。窗口抬高基线本身就能增大 Q，范围带也不是置信区间。

**粘贴答案有正确数字，为什么 unscored？** 检查是否只有一个明确 ANSWER/VERDICT 字段；是否附了括号、百分比、第二个答案、非有限数或错误参数。把数值放在精确格式中。不要放宽正则到随意截取数字，因为这样会误报含糊回复。

**检查器说 numeric_match，能说模型证明了公式吗？** 不能。它只检查固定参数数值；公式可能错误却偶然得到该数。人工应独立核对完整推导、参数域和渐近论证。

**直接 Modal 地址返回 401。** 没有服务端凭据时这是预期拒绝。访问产品应走获授权的匿名公共 Site；直接后端仍要求服务端凭据，不能把共享秘密复制到浏览器请求或公开 URL。

**构建器说 source differs / expected occurrence mismatch。** 原始 HTML 的字节或结构变了。应核查来源版本和审查范围，不要删除哈希/次数检查强行构建。需要接纳新源时，先做新来源审查并记录新哈希。

**stage 拒绝符号链接或已存在目录。** 使用全新的 stage 目录，并核查被拒路径。限制防止间接读入未审查数据；不要以递归复制整个仓库绕过它。

**线上内容与本地不一样。** Git push 不会自动发布 Sites。核对部署 ID、source commit、stage manifest 和真正远端响应。平台可能插入自身脚本，只有明确识别该变换并验证剩余字节时，才可解释哈希差异；不能忽略任意差异。

**可以公开访问 hBN 吗？** 用户本轮明确授权“包含，公开现有完整演示与 hBN 数据”，因此现有筛选演示和嵌入数据在匿名公开范围内；最新可达性查部署登记。这不自动包括未选入的原始模型、研究日志、密钥或新的模型 API 传输。

核查来源：[工作台逻辑](../web/app.js)、[回放逻辑](../web/replay.js)、[检查器](../hbn_demo/grade.js)、构建与 stage（开发归档路径：`../hosting/stage.py`）、[hBN 授权](../hbn_demo/authorization.json)、本轮远端验证（开发归档路径：`hbn-integration/FINAL_REVIEW.zh-CN.md`）。

### 30.2 AI 在环境里究竟看见和改变什么

建筑 agent 初始拿到题目、指定图纸、页空间与测量约定，可以读取文件、提取 PDF、渲染图、OCR、检查尺度、计算几何、定位对象。工具的输出、图像与错误是新的观察；agent 根据观察决定下一次动作。最后写 `/workspace/answer.json`，其中包含数量、单位、置信度、证据和假设。这是有多步决策的文件/容器环境；网页展示的是人类工作区和保存轨迹，不是实时模型聊天窗口。

真实回放中可见 read、bash、write、edit、glob、grep、todowrite 七种工具，参数例子与事件数详见第 20.1 节。框架工具名和底层工具要分开：bash 可以执行 Poppler、Tesseract、Python 或图像/几何库；安装了库并不表示模型一定用过，也不保证动作有价值。每步是否取得有用观察，应看参数、返回内容与最终工件。

任务结束或预算用尽后，独立可信 verifier 读取最终工件。正式 task 契约没有把人的评分/reveal API 列作 agent 工具，但公开站点仍可能被 public 网络 agent 主动访问。不能从“未列为工具”推断“无法访问”；新 allowlist 派生任务只表示配置意图，实际 Docker/Modal 出站尚需验证。原文提及 MCP，并不使现有 Harbor 文件/容器契约自动变成自定义 MCP 科研服务；当前不声称实现了该服务。

hBN 则面向人的解释与检查：选择预计算场或频率、移动视角、改变 Q 窗口、粘贴回复本地检查。页面没有自动选仿真、发 COMSOL/RCWA 请求、取得新实验观察并更新策略的科学 agent 闭环。真实科学评估是另列的四个数学 toy 任务；应明确各自的观察、工件和奖励来源。

### 30.3 难度为何有意义，以及何时不能这样说

有意义的困难应满足“资料足够、工具存在、正确策略可描述、失败与决策有关”。建筑题需要选择内边界或毛面积、合并尺寸串、排除题外楼板、辨别门窗与同一对象的多个线段。Kimi 西立面成功记录保留分段检查、排门与 18 个证据框；DeepSeek 楼板失败仍提交了 588 m² 与 27 框，却得到零数量/证据分，说明很多动作和框并不能代替正确范围。

失败成因要按证据强弱表达。楼板保存假设把 gross 与 inner faces 混在一起，是可见的不一致，但完整错误链仍需原图复核。science-a-03 的 rationale 则直接写出了错误常数，可以明确指出代数步骤。缺少提交或超时只表明该次运行失败，不能编成具体误读，也不能用基础设施故障证明任务具有学习价值。

奖励同样有取舍：建筑奖励 75% 数量、15% 证据、10% 校准，证据受数量分门控；合法零置信弃权为 0.1，无有效工件为 0。数字正确而没有框仍可能拿到较高数量/校准分，相关框也不证明完整推导。此环境优化的是可校验量算与证据相关性，不是形式化证明。评委若偏好更强过程要求，应讨论下一版契约并重评，不在旧结果上悄悄更改规则。

默认状态为 `prepared_not_executed`，在新目录生成独立任务副本、配置、逐文件来源哈希与 protocol.json。四类作业是 reference 一次、agent 三次、no-op 一次、stop-early 一次；每题六条，建筑计划 216 条、科学计划 24 条。三次 agent 由同一 agent 作业配置的 `n_attempts=3` 实现，需检查不同 trial/attempt 身份，不能误写成当前已有三个新 job 的结果。

输出目录非空或结果目录已经存在会拒绝，防止覆盖历史。要真正运行，必须选新的 run-id 并显式增加 `--execute`；模型凭据、Docker 或 Modal 前置条件、既有资源授权和预算也必须满足。默认预览从不因环境里已有密钥就隐式执行。本手册不提供秘密值，也不需要读环境文件。

执行命令结束时协议只记 `processes_finished_inspect_harbor_results`，不自动汇总稳定差距。后续应核对逐 trial 的任务集合、奖励、warning、超时与缺失项，保留完整分母，再分别报告三次结果和波动。历史 vector/clean/scan、smoke、已中断作业和两种模型不是三次同条件重复。

科学 reference 只读中性 input.json，属于解析 task-family policy；建筑 reference 仍为 privileged gold oracle。stop-early 先读 workspace 目录，再写合法零置信弃权；这验证停止工作的契约，不等于把一个学习模型在特定秒数强制中断。二者代码已实现且有离线检查，新 Harbor 轨迹仍须实际产生后才能称完成。

### 30.6 原始任务、网络派生与污染边界

新的 `blueprint_gym/judge_network.py` 定义 `blueprint-judge-egress-v1`。它要求原始 agent 环境是明确的 public 网络，要求 verifier 是 separate 且 no-network，并拒绝会覆盖网络策略的 agent 阶段字段。模型配置必须使用 `https://inference.verda.com/v1` 和预安装 agent；不允许由任意提供方 URL 绕过受审查主机。

协议准备时先核对所有 reference、agent、no-op、stop-early 使用同一显式任务集合。路径仅允许冻结的建筑或科学任务模式，重复任务、来源路径中的符号链接、任务内符号链接/设备/FIFO 等非普通文件均被拒绝。输出不能放入 tasks 或 science_demo/tasks 冻结树，也不能覆盖既有派生目录。

副本是独立普通文件，不是指向原任务的链接。除 task.toml 的 environment 网络段外，其余字节保持一致；该段改为 `network_mode="allowlist"`、`allowed_hosts=["inference.verda.com"]`。代码重新解析 TOML 并比对预期结构，确认没有顺带改奖励、超时、gold 或 instruction。原始与派生每个文件分别记录 SHA-256，并给完整文件列表计算 manifest hash。生成的 Harbor 配置使用绝对派生任务路径，避免切工作目录后误选同名原始任务。

protocol.json 的 task_snapshot 给出网络策略、verifier no-network、逐文件来源与 `runtime_egress_verified:false`。这是可检查的配置与来源链；它没有实际请求公共答案来证明阻断，也没有证明 provider 连通。Docker allowlist 依赖 Harbor egress control 和支持的 daemon/kernel；Modal 也需实际验证。镜像构建阶段可能下载依赖，与运行 agent 的允许主机是不同阶段；若运行时缺依赖而被拦，应诊断与预安装，不能静默切回 public。

因此，原 smoke/full/direct-local 配置只能作为历史复现路径，不是新的隔离评估推荐。即使未来证明网络阻断有效，公众已经看到的答案可能来自模型既有记忆，仍不能自动声称任务未污染。报告应同时保留任务来源版本、网络策略版本、完整分母、运行身份与未知项。原 160 条 trial 永不因创建派生任务而更换网络标签或重写成绩。
